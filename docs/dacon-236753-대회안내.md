## 2. 대회 배경 및 목적

블랙박스 영상은 교통사고 발생 과정과 차량 움직임을 확인하는 핵심 자료이나, 현재는 사고영상의 재녹화 여부 확인, 차량 진입·충돌 시점 분석, 가감속·조향 거동 분석 등이 감정관의 반복적 영상 확인·수작업에 의존하고 있음.

고의교통사고 분석을 위해서는 ① 입력 영상의 재녹화 여부, ② 피의차량의 진입·충돌 시점·진입 방향·회피 공간 여부, ③ 사고 구간의 차량 거동을 종합적으로 분석할 필요가 있음.

**목적**: 블랙박스 영상만을 입력으로 사고 분석에 필요한 주요시점·상황 및 차량 거동 특성을 자동 산출하여 감정관의 판단을 지원하는 AI 모델 개발.

## 3. 과제 구성 — 하나의 코드 제출로 3개 Stage 결과 산출

### Stage 1. 재녹화 여부 판별
- 하나의 영상 파일 = 하나의 평가 대상
- 각 영상에 대해 `ORIGINAL` 또는 `RERECORDED` 중 하나를 예측

### Stage 2. 사고 주요시점·상황 분석
- 입력은 원본 사고 영상을 프레임 단위로 추출한 이미지(영상별 폴더, 연속 프레임)
- 영상별로 충돌 프레임, 진입 프레임, 회피 공간 여부, 피해차량 진입 방향을 예측
- 제출 형식: 프레임 번호로 제시

### Stage 3. 차량 거동 특성 분석
- 실차 계측 원본을 10Hz로 구성한 영상 파일이 입력 (이미지 폴더가 아닌 영상 파일)
- 각 영상을 순서대로 분석하여 0.1초 단위의 가감속(`accel_label`) 및 조향(`steer_label`) 범주를 예측
- 영상과 함께 수집된 CAN 데이터는 "평가 정답 생성"에만 쓰이며, 비공개 평가 시 참가자 모델의 입력으로는 제공되지 않음
- 정지 상태(`STOPPED`)로 판정된 프레임은 조향 Macro-F1 산정에서 제외되지만, 제출 형식 일관성을 위해 **모든 프레임에 대해 steer_label을 출력**해야 함

> Stage별 세부 정의와 예시 영상은 대회 내 별도 공지 "[필독] Stage별 분석내용 및 예시 영상 안내"를 반드시 확인.

## 4. 데이터 (data 탭 원문 기준 — 폴더 구조·CSV 포맷 확정)

※ 다운로드한 `baseline.zip`에는 베이스라인 코드와 코드 이해를 돕기 위한 데이터 파일이 포함됨. **해당 파일을 그대로 제출하면 제출 횟수가 차감**되므로 주의.

### Stage 1 — 재녹화 여부 판별

```
data/stage1/videos/
├── TEST_S1_001.mp4
├── TEST_S1_002.avi
└── ...
```

출력 CSV:
```
ID,answer
TEST_S1_001,ORIGINAL
TEST_S1_002,RERECORDED
```

- 베이스라인의 재녹화(RERECORDED) 클래스 영상은 제출 구조 확인용으로, 재녹화 과정에서 나타날 수 있는 영상 특성을 **모사한 파생 예제**이며 실제 다른 기기로 재촬영한 데이터가 아님.

### Stage 2 — 사고 주요시점·상황 분석

```
data/stage2/images/
├── TEST_S2_001/
│   ├── frame_000000.jpg
│   ├── frame_000001.jpg
│   └── ...
├── TEST_S2_002/
│   └── ...
```

- 이미지 파일명에 포함된 프레임 번호는 원본 영상의 프레임 번호와 대응

출력 CSV:
```
ID,collision_frame,entry_frame,evasion_space,entry_side
TEST_S2_001,120,85,1,RIGHT
TEST_S2_002,244,198,0,LEFT
```

| 컬럼 | 의미 |
|---|---|
| `collision_frame` | 피의차량과 피해차량이 실제로 충돌한 프레임 번호 |
| `entry_frame` | 피해차량이 피의차량 차선에 최초로 진입한 프레임 번호 |
| `evasion_space` | 충돌 당시 회피 공간 여부 |
| `entry_side` | 블랙박스 영상 기준 피해차량 진입 방향 |

> ⚠️ Stage 2 **베이스라인은 충돌시점(collision_frame)만 학습**함. 진입시점·회피 공간 여부·진입 방향은 별도 정답 라벨로 학습되지 않으며, 네 항목 모두 출력은 하지만 학습되지 않은 세 항목의 값은 제출 형식 확인용 예시일 뿐 실제 예측 성능을 의미하지 않음(직접 학습 필요).

### Stage 3 — 차량 거동 특성 범주 산출

```
data/stage3/videos/
├── TEST_S3_001.mp4
├── TEST_S3_002.mp4
└── ...
```

출력 CSV:
```
ID,sample_index,accel_label,steer_label
TEST_S3_001,0,CONSTANT,STRAIGHT
TEST_S3_001,1,ACCELERATING,STRAIGHT
TEST_S3_001,2,DECELERATING,LEFT
```

| 컬럼 | 의미 |
|---|---|
| `sample_index` | 영상 내 0.1초 단위 순번, 0부터 시작 |
| `accel_label` | `ACCELERATING` · `DECELERATING` · `CONSTANT` · `STOPPED` 중 하나 |
| `steer_label` | `LEFT` · `STRAIGHT` · `RIGHT` 중 하나 |

> ⚠️ Stage 3 베이스라인은 코드 실행 확인용 **소규모·희소 라벨 데이터**. 실제 성능 확보를 위해서는 참가자가 별도 학습 데이터와 라벨링 전략을 직접 구성해야 함.

### 비공개 평가 데이터 적용 방식 (data 탭 명시)

- 배포 데이터는 Stage별 입력 형식·코드 실행 여부 확인용 예제만 포함. 실제 평가 데이터는 비공개.
- 참가자가 `submit.zip`을 제출하면 평가 서버에서 **동일한 Stage별 경로·데이터 구조**로 비공개 데이터가 자동 구성됨 (Stage1=영상 파일 / Stage2=영상별 폴더의 연속 프레임 이미지 / Stage3=10Hz 영상 파일 — 이 구조는 실제 평가 시에도 그대로 유지).
- 참가자는 비공개 평가데이터의 전체 수량·정답·원천정보를 확인할 수 없음. 제출한 추론 코드가 평가 서버에서 비공개 데이터를 입력받아 Stage별 예측 결과를 생성.
- **본 대회는 별도의 학습 데이터셋을 제공하지 않음.** 참가자는 법적 제한이 없는 학습 데이터를 직접 구성·확보해야 함.
- 배포된 공개 예제 데이터는 학습·추론 코드의 실행/입출력 형식 확인용이며, 실제 평가데이터와 구성·분포가 다를 수 있음.

## 5. 평가 방식 (Metric)

### Stage별 산식
- **Stage 1**: Macro-F1 (원본/재녹화 두 클래스 F1을 동일 가중 평균)
- **Stage 2**: 제출된 프레임 번호를 영상별 프레임–시간 대응정보로 초 단위 변환 후 정답시각과 비교
- **Stage 3**: 조향 기준 Macro-F1. 차량이 주행 중인 유효 프레임 대상, 정지(STOPPED) 프레임은 평가 제외되나 모든 프레임에 steer_label 출력은 필수

### 오답 처리 기준
- **Stage 1**: 결측값, 비수치값, 허용된 범주 이외의 분류값
- **Stage 2**: 예측값 누락, 결측값/비수치값, 음수 프레임, 해당 영상 범위를 벗어난 프레임, 허용된 범주 이외의 분류값

### 종합 점수
```
종합 점수 = (Stage1 × 0.2) + (Stage2 × 0.4) + (Stage3 × 0.4)
```

### 2단계 평가 구조
1. **1차 평가**: 대회 종료 시점 Public Score 기준 종합 점수(=Private Score) → **상위 15팀** 2차 진출
2. **2차 평가**: 2차 평가 자료를 제출하고 검증을 통과한 상위 15팀에 대한 종합 평가 진행 → **최종 상위 7팀** 수상팀 선정
   - 2차 진출 대상자 선정은 3개 Stage 점수의 종합 점수로 결정

## 9. 저작권 · 개인정보 · 참가 동의 (동의사항 탭 — 1차 조회 결과, 이번 갱신에서는 재조회하지 않음)

- **선발 아이디어(제출물)**: 저작권은 응모자 보유. 단, 주최기관은 "선발자를 선발하기 위한 검토·평가 등의 목적으로만 필요한 범위 내에서" 사용 가능하며 홍보·전시·교육 목적의 부수적 활용도 포함될 수 있음.
- **수상작**: 상금 지급 시 저작권이 주최기관에 **독점적으로 귀속**되며, 참가자는 주최기관의 서면 동의 없이 해당 저작물을 사용하거나 제3자에게 제공할 수 없음.
- **개인정보**: 주최기관·데이콘은 이름·주소·전화번호·이메일 등 개인정보를 수집·저장·공유·이용할 수 있으며, 한국을 포함한 해외로 이전될 수 있음.
- **데이터 이용 범위**: 대회 자료는 비영리 목적으로만 접근·사용 가능하며, 승인되지 않은 제3자에게 전송·배포 금지.

### 확정된 3-Stage 아키텍처

| Stage | 백본/구조 | 비고 |
|---|---|---|
| Stage 1 (재녹화 판별) | `torchvision.models.video.mvit_v2_s`, head를 2-class Linear로 교체 | 영상 1개를 3구간(slots=3)으로 나눠 각 구간에서 16프레임 클립 추출 → 각 클립을 모델에 통과시켜 RERECORDED 확률(softmax)을 얻고 평균 → 0.5 임계값으로 ORIGINAL/RERECORDED 결정 |
| Stage 2 (사고 시점/상황) | `resnet18`(ImageNet 사전학습, `fc`→Identity, 고정 특징추출기) + `Stage2Temporal`(BiGRU 2층, hidden 192, dropout 0.15 → 384차원) | 폴더 내 **모든 프레임**(stride=1)을 ResNet18에 통과시켜 512차원 특징 시퀀스 생성 → BiGRU로 시간 흐름 인코딩 → `collision_logits`/`entry_logits`(Linear 384→1)의 argmax로 충돌/진입 프레임 선택 → 두 시점의 hidden(768=384×2)을 concat해 `scene` 헤드(Linear768→192→ReLU→Dropout0.2→Linear192→4)에 통과, 앞 2차원=evasion_space, 뒤 2차원=entry_side(0=LEFT/1=RIGHT) |
| Stage 3 (거동 분석) | `mvit_v2_s` 공유 백본(head→Identity) + `accel`(Linear→4), `steer`(Linear→3) 2개 헤드 | 영상을 8프레임 단위로 순회하며 각 sample_index마다 과거 16프레임 클립(256리사이즈+224 센터크롭)을 구성해 accel_label/steer_label을 동시 예측(멀티태스크, loss는 두 CE의 합) |

### 학습 코드(`codeshare/14151`) 핵심 확인 사항 — ⚠️ 실사용 시 반드시 유의

- **`EPOCHS = int(os.getenv('EPOCHS', '1'))`** — 기본 1에폭. 배포된 학습 노트북은 "평가서버 호환 구조 확인용 스모크 테스트"이며, 실제 성능을 내는 학습 코드가 아님 (대회 데이터 탭에서 이미 경고한 "Stage 3 베이스라인은 코드 실행 확인용 소규모·희소 라벨 데이터"와 일치).
- Stage 1: `data/stage1/labels.csv`(컬럼: `path`, `label`)를 1건씩(배치 없이) 순회하며 AdamW(lr=1e-4)로 CrossEntropy 학습. 체크포인트에 `size=224`, `frames=16` 메타 저장.
- Stage 2: `resnet18` 가중치를 그대로 저장(`resnet18-f37072fd.pth`, 파인튜닝 없이 고정 특징 추출기)한 뒤, `data/stage2/labels.csv`(컬럼: `path`, `t_collision`)의 **충돌 시점만** 라벨로 BiGRU를 CrossEntropy 학습(AdamW lr=2e-4). 코드 주석: `# 공개 CCD 5건에는 충돌 구간만 공식 주석이 있어 나머지 헤드는 구조 확인용이다` — entry_frame/evasion_space/entry_side는 학습되지 않음(문서 4장에서 이미 언급한 내용과 정확히 일치).
- Stage 3: `data/stage3/labels.csv`(컬럼: `ID`, `frame_index`, `accel_label`, `steer_label`)로 accel(4클래스)·steer(3클래스) CrossEntropy 합산 손실로 MViTv2-S 공유 백본 학습.
- 재현성: `torch.manual_seed(20260825)`, `random.seed(20260825)` 고정.

### 추론 코드(`codeshare/14152`) 핵심 확인 사항

- 평가 서버는 `inference.py`의 `predict_stage1(data_dir, model_dir)` / `predict_stage2(...)` / `predict_stage3(...)` 세 함수만 호출. 각각 `pandas.DataFrame`을 반환해야 함.
- **submit.zip 실제 구조(코드로 검증됨)**:
  ```
  submit.zip
  ├── model/
  │   ├── stage1/best.pt
  │   ├── stage2/best.pt
  │   ├── stage2/resnet18-f37072fd.pth
  │   └── stage3/best.pt
  ├── inference.py
  └── requirements.txt
  ```
- 노트북은 `inference.py`를 코드 셀에서 직접 작성하지 않고, 노트북 내 마커(`# BASELINE_INFERENCE_PART`)가 붙은 셀들을 **노트북 JSON에서 추출·결합**해 생성한 뒤 `ast.parse`로 문법 검사 + 3개 필수 함수 존재 여부를 검사. ZIP 생성 후 ZIP 내부의 `inference.py`를 다시 열어 동일 검사를 반복(이중 검증).
- `_device()`는 `torch.cuda.is_available()`이 False면 즉시 RuntimeError — 평가 서버가 CUDA GPU라는 전제가 코드에 하드코딩됨.
- 추론 시 GPU 연산은 전 구간 `torch.autocast(dtype=torch.float16)` 사용.
- 공개 예제만으로 로컬 스모크 테스트를 수행하는 절차도 포함(임시 `sample_evaluation_data/` 생성 → 세 함수 실행 → `output/{stage}_submission.csv` 저장, 이 CSV는 제출 ZIP에는 포함 안 됨).
